# BiliMac 产品需求文档

版本：1.2 · 日期：2026-10-29 · 状态：P0、0.2 个人资料库与 0.3 视频互动实施范围

目标仓库：https://github.com/zZzzPpp12/bilibili-mac

## 1. 产品定义

BiliMac 是面向 macOS 的非官方哔哩哔哩原生客户端。通过原生浏览、搜索、播放、弹幕和个人内容管理，让用户在桌面上连续观看视频，并享受系统级窗口、键盘与播放体验。

产品暂名 BiliMac，界面语言首先支持简体中文，代码与工程文档采用可维护的模块命名。首版面向 macOS 26+、Apple silicon，使用 SwiftUI、AppKit 和 AVPlayer。产品独立设计 UI 和应用逻辑，允许在保留许可与明确来源的前提下复用 MIT 播放桥接组件。

## 2. 用户与使用场景

| 用户 | 目标 | 关键场景 |
| --- | --- | --- |
| 日常观看者 | 快速找到并持续观看视频 | 打开应用浏览推荐，切换视频，返回列表时继续小窗播放 |
| 搜索型用户 | 找到特定教程或创作者作品 | 输入关键词、BV 号或 B 站视频链接并播放 |
| 多分 P 观看者 | 保留学习进度 | 选择分 P、拖动进度、关闭后恢复上次位置 |
| 登录用户 | 使用自己的推荐与账号权限 | 扫码确认登录、刷新账号状态、主动退出 |
| 桌面效率用户 | 减少鼠标操作 | Cmd-F 搜索、空格播放/暂停、方向键快退/快进 |

## 3. 产品目标与评估

1. 首版完成“发现内容 → 选择视频 → 真实播放 → 返回继续浏览 → 恢复观看”的闭环。
2. 网络故障、账号限制和媒体不兼容均有可理解的状态及明确重试入口。
3. 播放会话独立于页面，正常导航不导致视频重启。
4. 账号凭据、私密内容和签名媒体 URL 不进入源码、日志及发布包。
5. 架构支持后续收藏、评论、离线下载和 iOS 适配。

首版不集成外部分析服务。验收通过本地测试和人工检查记录完成。以下为目标而非现有性能承诺：

| 指标 | 目标与测量方法 |
| --- | --- |
| 界面首屏 | 开机后暖启动 2 秒内显示可操作框架，不等待账号/网络完成 |
| 列表成功率 | 公开接口可用的受控网络下，连续 20 次请求至少 19 次成功；失败需可重试 |
| 播放起播 | 20 Mbps+、普通 1080P 测试样本，点击到媒体时间推进目标 5 秒以内；单独记录网络异常样本 |
| 播放连续性 | 手工完成首页/搜索/历史切换，播放项和进度连续 |
| 弹幕 | 普通弹幕中等密度下目标接近屏幕刷新率；暂停与不可见时停止不必要重绘 |
| 内存 | 完成关闭播放器后释放桥接与弹幕数据；不声称固定 RSS 上限，先建立采样基线 |

## 5. 信息架构与界面

主窗口使用三部分：固定导航侧栏、顶部搜索/账号工具栏、可滚动主内容。推荐和热门展示响应式视频网格；历史展示最近观看。设置独立系统窗口。视频详情位于主内容区，离开后右下角显示迷你播放器。

视觉基调采用浅/深色系统材质、粉色强调色、圆角封面与清晰的文字层级。导航常驻，登录入口可发现。有效操作都连接真实实现，规划功能只出现在文档。测试数据模式必须显示明确“演示数据”标识，不能作为线上成功证据。

## 6. P0 详细需求与验收

### F-01 内容浏览

游客可以查看推荐和热门。首次加载使用加载指示，不出现空白无说明页面；刷新失败保留已有列表并显示可重试错误。分页按 BV 号去重，正在请求时阻止重复分页，收到空页停止加载。切换导航取消过期请求，旧结果不能覆盖新页面。

封面独立显示加载状态。快速滚动、离屏后返回、切换导航不应让已取消的列表任务永久留下占位图。同一地址复用下载与成功缓存；缩略图失败尝试原始地址，失败不缓存。网络或图片失败显示清晰说明和“重试封面”；没有封面地址时显示“暂无封面”。重试只加载图片，不能误触视频播放，封面失败也不阻止通过标题打开视频。

验收：成功/空页/超时/服务端错误均有测试；人工从热门打开真实视频，返回后可继续浏览。封面需验证取消与重新出现、请求合并、失败后重试、原图回退、旧图片响应丢弃；真实推荐/热门封面下载并解码，快速滚动后可见卡片不持续停留在占位图。

### F-02 搜索与链接输入

输入框支持关键词、标准 BV 号和 `bilibili.com/video/BV...` 链接。BV 号必须严格验证长度与字符。首版不承诺任意短链接解析。关键词搜索调用签名接口，提交时清除上次分页状态；错误可重试原关键词。

验收：合法链接正确识别；普通关键词不误识别；连续提交两个关键词时只展示最后一次结果。

### F-03 登录与账号

使用官方扫码授权流程，由用户在 B 站 App 确认；不索取账号密码。网页会话只保留必要 Cookie。成功后先校验最小凭据信息，再写 Keychain，并刷新账号及推荐。取消登录保留原会话。网络错误不自动清除已有账号；仅明确服务端失效响应提示重新登录。

验收：二维码生成、待扫码、已扫码、已确认、过期、网络错误和取消都有明确状态；轮询关闭后停止；旧账号响应不得恢复已退出会话。真实扫码验收需用户主动完成。

### F-04 在线播放

通过详情取得 CID，播放地址接口取得 DASH 表示；选择系统兼容的视频与音频，经过 SIDX→HLS 本机桥接交给 AVPlayer。CDN 请求携带必要 Referer/User-Agent，不转发账号 Cookie 到媒体主机。起播展示准备状态，失败提供重试/其他画质。

最少支持 H.264 + AAC；HEVC 在可用时展示。首版优先验证 SDR 常见画质；仅展示接口实际可用的选项。不得把游客获得的低画质显示成高画质。

验收：合成分段媒体验证桥接可读取；在接口可用时手工验证真实视频媒体时间前进。编译通过、清单解析成功与 `readyToPlay` 均不能单独替代真实播放验收。

### F-05 播放操作与生命周期

支持播放/暂停、拖动进度、音量、分 P、画质、倍速与系统全屏。切画质先保存位置和播放意图，旧会话取消，新资源成功后恢复；暂停切换后保持暂停。新视频/关闭播放器时释放旧桥接。空格与方向键只在非文本输入状态生效。

验收：快速连切画质不出现旧视频覆盖；离开播放页继续小窗播放；关闭小窗后 AVPlayer 当前项清空；不让搜索框和设置输入被播放器快捷键拦截。

### F-06 普通弹幕

读取 Protobuf 分段，按媒体时间加载当前段及下一段，解析未知字段时安全跳过。支持右向左滚动、顶部、底部及反向普通弹幕。根据文字宽度、时间与速度分配轨道，控制最大可见数量。暂停、seek、隐藏与换视频时正确重建/停止。

首版设置：总开关、透明度；高级弹幕不会被执行。单段失败不阻止视频播放，允许后续重试，错误不持续遮挡画面。

验收：截断/畸形 Protobuf 不崩溃；时间单位正确；轨道边界有测试；暂停后弹幕保持媒体时间对应位置。

### F-07 历史与续播

本机历史保存视频 ID、标题/封面、最近 CID、分 P 位置、更新时间。周期性和暂停/离开时保存，最多保留 200 个视频。重新打开时恢复对应分 P，接近片尾的记录从头播放。仅本机历史，不将旧记录批量上传账号。

验收：正常退出/再启动可以续播；无效浮点与越界位置被清理；清空历史不删除凭据。

### F-08 设置与许可

设置通过 UserDefaults 持久化，外观支持跟随系统/浅色/深色。关于页显示版本、非官方说明、MIT 与第三方组件来源。应用本身不要求开启辅助功能、读取浏览器凭据或连接其他账号服务。

## 7. P1/P2 功能约束

### 7.1 本轮 0.2 范围与验收

**收藏。** 游客进入“我的收藏”显示扫码入口；登录后展示自己的全部收藏夹，区分公开/私密。切换收藏夹从第一页加载，后续页由服务端 `has_more` 决定，按资源 ID 去重；下架或无法识别的视频保留占位。快速切夹、退出或换号后，旧响应不得覆盖当前列表。刷新失败保留已展示内容，重试重新执行失败的那一页。

播放页“收藏到…”打开多选窗口，初始勾选来自当前视频在各收藏夹的状态。勾选只改本地草稿；保存时提交“新增集合/删除集合”，没有变化时不发写请求。保存期间禁止重复保存和关闭。取消丢弃勾选。新建收藏夹支持 1–20 字名称和私密选项，点击创建立即同步账号，并明确说明取消窗口不会删除新建夹；新夹自动勾选，视频仍需保存后加入。

**稍后再看。** 当前官方接口一次返回整个列表（最多 100 条），客户端不虚构下一页。播放页能加入或移出；列表能播放或单条移除，列表移除需确认。操作前必须已成功读取当前账号状态，同步中禁止重复操作。只有明确成功回执才更新按钮和列表；列表满、会话过期、稿件下架等业务失败展示实际原因。

**只读评论。** 播放页按稿件 aid 加载评论，支持最热/最新、刷新、加载更多和楼中楼逐页展开。顶置条目与普通列表去重；使用服务器返回的不透明 offset，不自行推算页码。即使 offset 相同，只要返回新评论仍可继续；无新内容且服务端仍有下一页时显示可重试错误，不丢失已有正文或推进游标。切视频、换排序、换号后丢弃旧响应。楼中楼错误与主列表隔离。展示用户名、正文、时间、地区（若有）和点赞数；表情显示文字，纯图片等内容显示占位，本轮不含图片预览、点赞、回复和发布。

**写入结果确认。** 收藏、新建夹、稍后再看只由明确点击触发，包含 CSRF 和当前账号校验。网络中断、非明确业务响应或回执缺失时，禁用再次写入，提示先刷新核对；只有读取成功后才能继续，不自动重试 POST。取消旧会话的 UI 更新不代表能撤销服务器已接收的操作。

**验证。** 使用独立模拟会话检查端点、表单编码、CSRF、分页与异常；可控延迟检查重复点击、账号/视频/收藏夹/排序切换。公开评论接口单独做游客只读检查，不在测试中读取 Keychain 或修改用户真实收藏。真实扫码后的收藏增删与私密权限，由账号本人验收。

### 7.2 本轮 0.3 视频互动范围与验收

**点赞。** 播放页显示当前账号是否已赞，点击执行点赞或取消赞；游客点击引导登录。读取状态失败时不猜测。请求期间禁止重复提交，明确成功回执后才更新按钮；失败后先刷新核对。评论区继续只读，本轮点赞对象是视频。

**投币。** 读取该稿件已投数量、原创/转载类型、作者和当前账号硬币余额。原创最多 2 枚，转载最多 1 枚；自己投稿、余额不足和已投满均显示原因。点击投币打开确认窗口，在可投范围内选择 1/2 枚，可选同时点赞，显示本次消耗和不可撤回说明。取消不提交；确认后先重新核对状态，任何余额或互动变化都更新页面并要求重新确认，不沿用旧确认直接花费。已有点赞不因附加点赞失败而被取消。

**三连。** 使用服务端单次三连接口，包含点赞、投币和加入默认收藏夹；本次最多消耗尚未投满的硬币数量。提交前要求余额覆盖该上限；已经完成三项时禁用重复三连，投满后仍缺点赞/收藏时可确认无需新增投币的三连。确认窗口说明默认收藏夹、硬币上限及部分成功的可能性，取消不提交。按回执分别保留点赞、实际新增硬币与收藏结果，不把部分成功显示为全部完成，也不自动补投或重复三连。收藏成功后刷新账号收藏列表。

**并发与未知结果。** 一个视频的请求期间禁用重入；暂离后返回仍保留该视频的处理中/待核对状态。账号切换立即清空旧上下文，迟到回执不得恢复账号、更新新账号状态或刷新新账号的收藏。网络中断、回执缺失、异常投币数量和三连部分成功均先刷新核对，再允许下一次操作。刷新只发 GET，绝不自动重发 POST；刷新失败保留已知结果与待核对标记。

**服务约束与验收。** 互动只携带当前扫码账号、CSRF 和官方接口返回的浏览标识，标识仅驻留本会话内存，不制造标识、不读取浏览器凭据。遇到官方验证/风控提示，提供官方视频链接，由本人处理后刷新，不自动解决验证或绕过限制。测试通过模拟接口验证所有写入、余额与投币限制、取消/重复确认、结果不明、部分成功和会话隔离；联网只检查公开只读接口与播放。真实点赞、投币及三连需本人登录后验收，自动测试不消耗真实硬币。

### 7.3 其他后续能力

- 评论发布（后续）：提交回执与公开可见评论分开，不把已提交显示为已公开。
- 互动：防重复提交；投币/三连遇到未知结果只刷新状态，不自动重试写入。
- 离线：任务索引持久化、分块前缀恢复、签名 URL 刷新后验证媒体身份、直通合轨和发布检查点。文件索引落盘后才清理临时块。
- 消息：每个会话独立草稿和滚动位置；按服务端游标加载；所有发送均需用户明确操作。
- 高级弹幕：只解释受支持的绘制语法，不执行网络请求与任意代码；不支持模式给出清晰兼容说明。
- iOS：复用模型、API、播放准备及存储协议，独立实现 UIKit/SwiftUI 生命周期，不直接复用 macOS 视图。

## 8. 状态与异常规范

所有列表使用 idle/loading/loaded/empty/failed 语义；保留已有内容的刷新错误通过非阻断提示显示。视频使用 preparing/ready/playing/paused/buffering/failed/closed 语义，不将 loading 布尔值当成全部状态。

| 错误 | 用户反馈 | 处理 |
| --- | --- | --- |
| 断网/超时 | 网络暂不可用，可重试 | 保留内容和账号 |
| HTTP 412 / 风控 | 请求暂受限制，请稍后重试或登录 | 不无限重试、不绕过验证 |
| 未登录/会话失效 | 登录后使用或重新登录 | 不清空本机历史 |
| 视频下架/权限限制 | 视频不可用或当前账号无权限 | 返回、其他视频 |
| 清单无兼容轨道 | 当前媒体暂不支持 | 重试或更换画质 |
| 播放器失败 | 显示简洁错误与重试 | 释放失败会话 |
| 弹幕失败 | 小型状态提示 | 保留视频播放 |
| 磁盘/Keychain 保存失败 | 登录或进度未保存的明确提示 | 不伪报成功 |

## 9. 技术架构与模块边界

```text
SwiftUI / AppKit
    ↓
AppStore + LibraryStore + PlayerController
    ↓                         ↓
BilibiliClient            PlaybackBridge
    ↓                         ↓
URLSession / Keychain     SIDX → HLS → localhost → AVPlayer
    ↓
B 站公开可访问接口与媒体 CDN
```

核心模块：

| 模块 | 职责 | 依赖边界 |
| --- | --- | --- |
| Domain | 视频、详情、账号、历史、弹幕、媒体清单 | Foundation；媒体表示可适配 Vendor 模型 |
| Networking | URLSession、WBI、HTTP/业务错误、二维码 | 不依赖 SwiftUI |
| Persistence | Keychain、历史 JSON、偏好 | 不记录媒体签名 URL |
| Playback | AVPlayer、桥接生命周期、画质/进度 | 可被多个视图引用 |
| Danmaku | Protobuf、分段、调度、原生图层 | AVPlayer 时间源 |
| App/UI | 导航、列表、搜索、播放页、登录与设置 | 不直接拼接业务请求 |

首版使用本地 MIT 播放桥接子集，保留原许可与固定来源提交，仅编译所需模块，避免不使用的新 SDK 音频处理 API 影响 Xcode 26 构建。新应用采用自己的 Bundle ID、Keychain service 和 UserDefaults suite；不读取参考项目的本机用户数据。

## 11. 安全、隐私与开源

1. 凭据仅保存在系统 Keychain，日志不输出 Cookie、CSRF、账号 token 和完整签名媒体地址。
2. 只将会话 Cookie 发送到对应官方业务主机；媒体 URL 和本机桥接需要各自的地址校验。
3. 本机 HTTP 服务仅监听回环地址，随机会话路径并校验 Host，关闭播放会话时停止服务。
4. 源码仓库不提交实际账号、观看内容、私信、媒体缓存、签名证书、描述文件及构建产物。
5. 本项目应用代码使用 MIT，复用组件保留版权、来源提交与本地改动记录。品牌与视频权利归原权利人。
6. 不内置遥测。网络与账号操作均由用户主动使用对应功能触发。

## 12. 无障碍与性能

所有图标按钮有可访问名称，主要操作提供键盘路径；不以颜色作为唯一状态表达。文本输入不被播放器快捷键劫持。遵循减少动态效果和系统外观。加载错误应可被辅助技术读取。

网络、解码及文件操作不阻塞主线程；任务取消与响应代次检查必须覆盖换页、换视频、关闭弹窗和退出账号。封面解码有尺寸/缓存上限，弹幕有数量上限，视频使用流式桥接不在内存保存完整文件。

## 15. 风险与决策

| 风险 | 影响 | 决策 |
| --- | --- | --- |
| 官方接口变化/风控 | 列表、登录或播放失败 | 集中适配、可重试、保留用户状态 |
| 账号/视频权限 | 高画质不可用 | 按实际清单展示，不伪造能力 |
| SDK 差异 | 项目无法编译 | 仅引入首版需要的兼容播放组件；记录工具链 |
| 编码/分段差异 | 黑屏、时长不全、seek 异常 | H.264/AAC 为基本验收，扩展格式单列 |
| 大量弹幕/封面 | 内存和主线程压力 | 数量上限、按需加载、后台解码 |
| GitHub 权限 | 推送阻塞 | 先交付本地完整结果，再按现有认证尝试推送 |

本版决策：macOS 优先、原生实现、无自建服务端、无默认遥测、先完成可观看闭环，再扩展账户写操作和离线体系。
