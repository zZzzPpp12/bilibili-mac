# 0.6.0 自研播放桥实现与验证状态

更新：2026-10-29。macOS 开发预览，build 8。自研桥的基础点播闭环已接入默认路径；后续稳定性与完整来源清理尚未完成。旧版本记录保留在下方。

## 本轮播放桥改造

新增本项目 `BiliMacMedia` target，自行实现媒体类型与官方来源策略、有限 Range 读取、SIDX v0/v1 直接引用、内存 HLS 目录、虚拟媒体分片和会话回环服务。`BiliMacCore` 的播放描述及 `PlayerController` 已使用这些接口；系统 AVPlayer 继续负责解码与音画同步。当前 `Package.swift` 无外部包依赖，无旧桥自动回退。Release 链接清单已核对，不含 Vendor 或原 BiliPlayback / BiliModels / BiliNetworking 模块。

- 固定 H.264/AAC 点播；过滤未验证的 HEVC 选项。轨道准备时每轨最多检查 3 个候选来源，成功后固定来源，不在响应中拼接不同 CDN。
- 上游媒体仅携带必要 User-Agent / Referer，禁用 Cookie、凭据、缓存与重定向。先校验 206、Content-Range、总长度、编码和内容类型，再接收有界正文；短/长正文、忽略 Range、HTML 错误页明确失败。
- 索引和初始化各最多 2 MiB；单次媒体读取最多 16 MiB，媒体交付并发为 2，配额持有到下游发送结束。当前按有限分片完整缓冲，再以 64 KiB 块交付，并非细粒度上游流式转发。约 32 MiB 是两份媒体正文上限，不是整个进程的内存承诺。
- 回环服务仅监听 127.0.0.1 随机端口，验证 Host 和随机会话路径；只允许登记资源的 GET/HEAD 和单范围 Range，限制连接/头大小/时间，拒绝请求体、冲突头和未知路径。关闭取消连接、传输与等待配额，重复关闭安全。
- 修复暂停续播/切画质只依赖 EXT-X-START 时实际时钟可能归零的问题：播放项就绪后先完成精确 seek，再结束加载并应用当前播放意图；迟到定位不能覆盖新播放项。媒体失败展示脱敏原因和现有重试入口。

本项目生成器从自造移动色块像素和 660 Hz 节拍 PCM 编码出新的 8 秒测试媒体，已移除当前测试目录中原先来自上游的两段素材。FFmpeg 只作开发编码工具，应用和 CI 不依赖其安装；参数及摘要见 `Tests/BiliMacTests/Fixtures/README.md`。数值 SIDX 黄金样例另行手写，音频由系统解码验证为非静音 PCM，不以生成器和解析器互相证明。

## 0.3.1 封面修复记录

根因已在原生窗口复现：启动后首屏图片正常，快速滚动到后续卡片后，多张封面进入 `NSURLErrorDomain -999`（请求被取消）。原实现把 `AsyncImage` 放在 `LazyVGrid` 单元格里，只处理成功分支，离屏/预加载取消后既没有恢复机制，也没有失败说明。诊断构建显示了实际错误码；相同官方地址的原图与 WebP 缩略图用 URLSession + 原生解码均成功，独立 AsyncImage 窗口也能显示，不能把此次故障归因为资源不真实、CDN 403 或系统不支持 WebP。

- 新增 `CoverImageLoader` actor，合并同地址的下载。共享下载任务不随某个离屏单元格的取消而中止；单元格重新出现可等待原请求或读取成功缓存。
- 只缓存解码成功的图片，缓存成本限制 64 MiB / 128 项，解码最长边 1280 像素；请求超时有限，失败不无限自动重试。
- 官方图片地址规范为 HTTPS；保留签名查询和已有尺寸后缀，避免重复拼接。可选 640×360 缩略图失败时，尝试未改动的原始地址。图片会话不使用账号 Cookie 或凭据。
- 封面显示加载状态；网络/访问/解码失败显示说明与“重试封面”；缺失或不可用地址显示“暂无封面”。旧 URL 或已取消单元格的迟到结果不覆盖新图。
- 重试按钮与播放按钮平级；封面失败仍可点击标题播放。所有卡片共用这条链路，覆盖推荐、热门、搜索、历史、收藏、稍后再看及失效收藏项。

投币和三连均需应用内确认；最终提交前重新读取同一账号、同一稿件的余额和关系。状态变化时不发送 POST，更新页面并要求重新确认。已经完成三项时禁止重复三连。若本次回执 coin=false，不按 multiply 字段再次扣减余额。

必要浏览标识由官方 finger/spi 返回，只保存在当前会话内存，重新登录会清除。认证 POST 使用七条端点允许列表、CSRF、官方视频 Referer，不跟随重定向。风险/验证错误提供官方视频链接，由本人处理后刷新，不自动补发互动或处理验证。
